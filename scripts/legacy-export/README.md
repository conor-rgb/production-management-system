# Legacy Export Utility

This utility exports Prisma data in read-only mode for analysis and migration mapping. The current direction is in-place finance/Drive consolidation, not a mandatory full platform rebuild. See [the current brief](../../BRIEF.md) and [export scope](../../docs/rebuild-audit/EXPORT_PLAN.md).

A redacted export is not an operational backup: it omits credentials, sessions and file binaries. Historical July reports do not validate today's data. DriveConnection refresh-token fields must remain redacted under the generic rules below.

Run from the repository root through the backend package scripts:

```bash
npm --prefix backend run legacy:export:dry
npm --prefix backend run legacy:export
npm --prefix backend run legacy:validate
```

Outputs are written under `exports/legacy-export/<timestamp>-<mode>/`. Full exports include one JSON and one CSV file per exported Prisma model, plus:

- `manifest.json`: schema version, Git commit, model counts, exported fields, redacted fields, and file checksums.
- `errors.json`: export errors, if any.
- `validation-results.json`: generated by validation.
- `exports/VALIDATION_REPORT.md`: human-readable validation summary.

Read-only guarantees:

- Uses Prisma `count`, `findMany`, and `findFirst` only.
- Does not call update, delete, create, upsert, raw write SQL, migrations, or external APIs.
- Preserves original IDs, timestamps, scalar foreign keys, null values, arrays, and JSON values.
- Can be run repeatedly; each run creates a timestamped export directory.

Redaction rules:

- Excludes the `Session` model entirely.
- Redacts `Settings.password`.
- Redacts `EmailAccount.encryptedPassword`, `encryptedAccessToken`, and `encryptedRefreshToken`.
- Redacts any scalar field whose name matches password, secret, access token, refresh token, session, JWT, API key, or client secret patterns.

The exporter intentionally preserves foreign-key scalar fields so relationships can be reconstructed without exporting sensitive credential material.
